## Future Notes — Accounting Integration

*(Do not implement until explicitly requested)*

1. **Double Counting Audit — Executive Dashboard + Reports:** Review dashboard KPI cards and report totals to ensure they don't double-count amounts from both `Transaction` (legacy) and `JournalEntry` (GL) systems. Each approval currently writes to both; any report summing both tables will overstate actuals.

2. **Expense Status REVERSED / CANCELLED:** The current `cancelApproval()` sets status back to `REJECTED` — semantically imprecise for a reversal. Consider adding a `REVERSED` or `CANCELLED` status value in a future migration to express the cancellation clearly.

3. **paymentMethod on Expenses:** Phase B always credits CASH (1000). When `paymentMethod` field is added to the `Expense` model, route the GL credit to CASH (1000), BANK (1010), or ACCOUNTS_PAYABLE (2000) accordingly.

4. **Payroll → GL Integration:** Payroll module has no double-entry GL wiring. PAYROLL_EXPENSE (5100) account exists in SYSTEM_ACCOUNTS but is not yet used automatically. Deferred.

5. **Purchase Invoice → GL Integration:** `invoices.accounting.ts` logs `PURCHASE_INVOICE_GL_POSTING_SKIPPED` for purchase-direction invoices. Accounts Payable + Purchases GL posting deferred.
