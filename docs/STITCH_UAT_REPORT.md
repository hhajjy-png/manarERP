## تقرير إصلاح المشكلة #1 — بطاقات Dashboard في الوضع الفاتح

**تاريخ الإصلاح:** 2026-06-10
**الملف المُعدَّل:** `frontend/src/styles/stitch-full.css` (السطور 219–329)

### السبب الجذري (Double Bug)

**خطأ أول — أسماء كلاسات خاطئة:**
كانت `stitch-full.css` تستهدف كلاسات غير موجودة في `dashboard.css`:
- `.db-kpi-card` (غير موجودة) ← الصحيح: `.db-kpi`
- `.db-kpi-value` (غير موجودة) ← الصحيح: `.db-kpi-val`
- `.db-chart-card`, `.db-panel` (غير موجودتان) ← الصحيح: `.db-card`
- `.db-panel-title`, `.db-chart-title` (غير موجودتان) ← الصحيح: `.db-card-head h3`
- `.db-alert-panel`, `.db-ops-card`, `.db-attendance-card` (لا وجود لها)

**خطأ ثانٍ — خلفيات مُضمَّنة (Hardcoded) تتجاوز CSS variables:**
حتى مع تصحيح الأسماء، كانت هذه العناصر تستخدم `rgba(31, 41, 55, ...)` مُضمَّنة في `dashboard.css` — لا تتأثر بتغيير `--db-card`. الحل: `background: var(--surface) !important`.

### طريقة الإصلاح

استُبدلت كتلة السطور 219–354 بالكاملة بسيلكتورات صحيحة:
- `.db-kpi` ← `background: var(--surface) !important` + `backdrop-filter: none !important`
- `.db-card` ← نفس المعالجة
- `.db-card-head` ← `background: var(--surface-2) !important`
- `.db-aw` ← `background: var(--surface) !important` مع استثناء للألوان الحالة
- `.db-actions` ← `background: var(--surface-2) !important`
- إضافة `.db-kpi-val`, `.db-kpi-sub`, `.db-stat-val`, `.db-stat-sub`

**سلامة Dark Mode:** `var(--surface)` = `#1e293b` في الوضع الداكن — قريب جداً من `rgba(31, 41, 55, ...)` الأصلي. الإصلاح آمن تلقائياً.
