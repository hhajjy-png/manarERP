# AI-2.5 Professional Business Skills Expansion — Design Spec

**Date:** 2026-06-29  
**Phase:** AI-2.5  
**Scope:** Frontend only — no backend changes, no new APIs, no migrations  
**Approach:** Layer-Driven (Type-First → ResultCard → Skills → Router → Polish)  
**Status:** Approved — ready for implementation

---

## 1. Overview

AI-2.5 expands the deterministic Skill framework (introduced in AI-2) into a production-grade business analysis platform. It adds 10 packages of capability on top of the existing 6-skill engine without changing any backend code, database, or API.

The system remains fully deterministic, read-only, offline-only, and free of LLM/RAG/OCR.

### Packages

| Package | Name | Scope |
|---|---|---|
| A | Expand Business Skills | New intents + richer analyses per skill |
| B | Skill Capability Levels | `capabilityLevel` badge on every result |
| C | Rich Sources Panel | Dataset provenance, record count, completeness |
| D | Explainability Panel | Deterministic step-by-step processing trace |
| E | Data Quality Score | Shared quality engine → score + issue pills |
| F | Cross-Skill Navigation | Related skills + related pages chips |
| G | Action Cards | openModule, copySummary, exportResult, print |
| H | Skill Metadata | Version, generation, capabilities, modules |
| I | Developer Diagnostics | Router/skill/API timing, record count (DEV only) |
| J | UI Polish | CSS additions, blocked-router card, phase badge |

---

## 2. Strict Rules

- **Frontend only** — no backend changes
- **No new APIs** — use existing REST endpoints only
- **No migrations** — no schema or DB changes
- **No LLM, RAG, OCR, AI provider** of any kind
- **No permissions changes** — no new RBAC keys
- **Backward compatible** — existing AI-2 SkillResult objects and localStorage history must render without errors
- **No commit / merge / tag / push** until user explicitly instructs

## 4. Shared Quality Engine (`frontend/src/ai/qualityEngine.ts`)

A pure function — no side effects, no API calls, no imports from skill files.

### 4.1 Input

```typescript
interface QualityInput {
  totalRecords: number;
  completeRecords: number;       // records with all required fields present
  warningCount: number;          // number of warning-severity items found
  missingFields: string[];       // names of expected-but-absent data fields
  customPenalties?: Array<{ reason: string; points: number }>;
}
```

### 4.2 Algorithm

```
base = 100
completeness penalty  = (1 - completeRecords/totalRecords) × 40    [if totalRecords > 0]
warning penalty       = warningCount × 5                            [capped at 20]
missing field penalty = missingFields.length × 5                   [capped at 20]
custom penalties      = sum of customPenalties[].points            [capped at 20]

qualityScore = max(0, round(base - completeness - warning - missing - custom))
```

### 4.3 Issue generation rules

- completeness < 70% → `danger` issue "بعض السجلات تحتوي على بيانات ناقصة"
- completeness 70–89% → `warning` issue "بعض السجلات غير مكتملة"
- warningCount > 0 → `warning` issue "توجد {n} تنبيهات في البيانات"
- each `missingField` → `info` issue "حقل {field} غير متوفر في مصدر البيانات"

### 4.4 Exports

```typescript
export function computeQuality(input: QualityInput): {
  qualityScore: number;
  qualityIssues: QualityIssue[];
};
```

## 5. ResultCard Rendering (`frontend/src/ai/ResultCard.tsx`)

### 5.1 Render Order

All new sections are optional — hidden completely when their field is absent.

```
1.  Header                    (existing — title + skill badge)
2.  Capability badge          [B] — appended to header chip row
3.  Summary                   (existing)
4.  Statistics row            (existing)
5.  Highlights                (existing, optional)
6.  Data cards                (existing, optional)
7.  Data Quality Gauge        [E] — if qualityScore present
8.  Explainability Panel      [D] — if explanationSteps present, collapsed by default
9.  Rich Sources Panel        [C] — if richSources?.length > 0
10. Warnings                  (existing)
11. Action Cards              [G] — if actions present
12. Related Skills / Pages    [F] — if relatedSkills or relatedPages present
13. Skill Metadata            [H] — collapsed by default, toggled by ⓘ button
14. Sources chips             (existing)
15. Follow-up questions       (existing)
16. Footer (exec time)        (existing)
17. Dev diagnostics           [I] — DEV only, extends existing dev panel
```

### 5.2 Section Specs

**[B] Capability Badge**  
Injected into `.ai-rc-header-chips` next to the existing skill badge.
- `complete` → green pill "مكتملة ✓"
- `partial` → blue pill "جزئية ~"
- `preview` → amber pill "معاينة ◉"
- `comingSoon` → muted grey pill "قريباً ○"

**[E] Data Quality Gauge**  
Label: "جودة البيانات — {score}/100"  
Full-width track, fill width = `score%`, color thresholds:
- ≥ 80 → green (`.ai-rc-quality-fill--high`)
- 60–79 → amber (`.ai-rc-quality-fill--medium`)
- < 60 → red (`.ai-rc-quality-fill--low`)

If `qualityIssues` present: pill row below bar, color-coded by severity.

**[D] Explainability Panel**  
Header: "⚙ كيف تم إعداد هذه النتيجة؟" with chevron toggle  
Collapsed by default. Body: numbered step list.  
Each step: number circle | `labelAr` | optional `detailAr` (smaller text below)

**[C] Rich Sources Panel**  
Section label: "📊 مصادر البيانات"  
Table-style grid, one row per `RichSource`:  
columns: dataset name | module | records (or "—") | date range (or "—") | mini completeness bar | sourceType chip

**[G] Action Cards**  
Section: horizontal flex row of small solid buttons.  
Available → active button. `available: false` → muted disabled + `title="قريباً"`.  
- `openModule` → `navigate(payload)`  
- `copySummary` → `navigator.clipboard.writeText(result.summary)`  
- `exportResult` → download `.txt` with result title + summary + statistics  
- `print` → `window.print()` (existing print CSS handles layout)

**[F] Cross-Skill Navigation**  
Section label: "🔗 تحليلات ذات صلة"  
Two sub-rows (each only if non-empty):
- Related skills → chip row; click fires `onFollowUp(promptSuggestion)`
- Related pages → chip row; click fires `navigate(path)`

**[H] Skill Metadata**  
Collapsed by default behind "ⓘ" toggle button.  
Reveals chip cloud: version (monospace), skillGeneration (amber tint), status, capabilities, dependentModules, lastUpdated.

**[I] Dev Diagnostics**  
Extends the existing `.ai-rc-dev-grid` (DEV build only).  
New rows: Router ms | Skill ms | API ms | Records analyzed | Cards rendered.  
Only rendered when `diagnostics` field is present.

## 6. Quality Engine Integration Per Skill

Each skill computes quality inputs from its own API response data and passes them to `computeQuality()`. Skills do not invent their own scoring formulas.

| Skill | `totalRecords` | `completeRecords` | `warningCount` | `missingFields` |
|---|---|---|---|---|
| Bank Statement | workspace transaction count | transactions with description + amount + date | flagged/review transactions | `['endDate']` if absent |
| Payroll | payroll record count | records with employee + netSalary | unpaid records | `['department']` if employee.department null |
| Dashboard | trend point count (6) | trend points with both revenue + expense | 0 (operational alerts handled separately) | `['trend']` if trend endpoint fails |
| Expenses | stats.count | always = count (aggregated) | pendingCount | `['bySupplier']` if absent |
| Contracts | contract record count | contracts with endDate + monthlyTransportValue | expiring ≤30 days count | `['endDate']`, `['monthlyTransportValue']` if absent |
| Reports | 0 | 0 | 0 | n/a — quality score omitted |

### Tier 3 — Reports Discovery

#### 7.6 Reports

**Replaces the existing stub entirely.**

**Strategy:** Two-layer approach:
1. Attempt `GET /reports` — parse and display available report types if the endpoint returns a catalogue
2. If endpoint unavailable / returns non-catalogue data → fall back to hardcoded registry of known report types

**Known report types (hardcoded registry):**
- مالي — تقرير الأداء المالي
- رواتب — تقرير الرواتب والمرتبات
- عقود — تقرير العقود النشطة
- مصروفات — تقرير المصروفات التفصيلي

**Intents:**
- `discover` (default) — full catalogue with descriptions + recommended report + open Reports Center action
- `recommend` — single recommended report with rationale

**What remains `comingSoon`:** report output summarization, period comparison, insight extraction

**Enriched result populates:**
- `capabilityLevel`: `'partial'` (discovery works; summarization coming)
- `relatedPages`: `/reports`
- `relatedSkills`: Dashboard, Bank Statement (as financial summary proxies)
- `actions`: openModule (`/reports`) only
- `skillMetadata`: version `"2.5.0"`, capabilities `["discover","recommend"]`
- `qualityScore`: omitted (no data to score)
- `richSources`: omitted
