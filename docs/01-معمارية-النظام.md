# معمارية النظام — نظام إدارة أعمال شركة المنار

**شركة المنار لإنشاء وإصلاح الطرق والشوارع والأرصفة ومستلزمات الطرق ذ.م.م**

> وثيقة معمارية (System Architecture) — الإصدار 1.0
> نظام يعمل بالكامل محليًا (Offline-First) على أجهزة Windows.

---

## 1. نظرة عامة على المعمارية

النظام تطبيق سطح مكتب (Desktop Application) مبني على **Electron**، يجمع بين واجهة أمامية حديثة بـ React وطبقة خلفية محلية بـ Node.js، وقاعدة بيانات **SQLite** محلية لا تحتاج أي خادم خارجي ولا اتصال بالإنترنت.

تتبع المعمارية نمط **Clean Architecture** مقسّمة إلى ثلاث عمليات (Processes) رئيسية تتواصل عبر قناة آمنة:

| العملية | المسؤولية | التقنية |
|---------|-----------|---------|
| **Main Process** | إدارة دورة حياة التطبيق، النوافذ، الوصول للملفات، تشغيل الخدمة الخلفية، النسخ الاحتياطي | Electron + Node.js |
| **Renderer Process** | واجهة المستخدم بالكامل (RTL عربية) | React + TypeScript + MUI |
| **Backend Service** | منطق الأعمال، الوصول لقاعدة البيانات، الصلاحيات، التقارير | Node.js + Express + Prisma |

> **قرار معماري:** يتم تشغيل الـ Backend (Express + Prisma) داخل الـ Main Process كخدمة محلية على منفذ داخلي (مثل `127.0.0.1:48211`) لا يُفتح للشبكة الخارجية. هذا يفصل منطق الأعمال عن الواجهة بشكل نظيف، ويسهّل لاحقًا تحويل النظام إلى Client/Server في حال احتاجت الشركة عدة أجهزة على شبكة محلية (LAN).

## 3. طبقات الـ Backend بالتفصيل (Clean Architecture)

نطبّق فصل المسؤوليات عبر أربع طبقات، مع تطبيق مبادئ **SOLID** و**Repository Pattern** و**Service Layer**:

### 3.1 طبقة العرض (Presentation Layer)
- **Routes**: تعريف نقاط النهاية (Endpoints) لكل وحدة (`/api/customers`, `/api/projects` ...).
- **Controllers**: استقبال الطلب، استخراج المدخلات، استدعاء الـ Service، إرجاع الاستجابة. لا تحتوي منطق أعمال.
- **Middleware**: المصادقة (JWT/Session)، فحص الصلاحيات (RBAC)، التحقق من المدخلات (Validation)، تسجيل العمليات (Audit)، معالجة الأخطاء.

### 3.2 طبقة التطبيق (Application / Service Layer)
- تحتوي كل منطق الأعمال: حساب الأرباح، اعتماد المصروفات، توليد الفواتير، احتساب الرواتب.
- كل وحدة لها Service خاص بها (`CustomerService`, `ProjectService`, `InvoiceService` ...).
- تنسّق بين عدة Repositories عند الحاجة (مثال: إنشاء فاتورة يحدّث الفاتورة + بنودها + قيد محاسبي).

### 3.3 طبقة المجال (Domain Layer)
- **Entities / Types**: نماذج TypeScript تمثّل الكيانات.
- **Validation Schemas**: قواعد التحقق باستخدام **Zod** (مثال: رقم الهاتف، البريد، القيم الموجبة).
- **Business Rules**: قواعد ثابتة (مثال: لا يمكن حذف عميل له مشاريع نشطة).

### 3.4 طبقة البنية التحتية (Infrastructure Layer)
- **Repositories**: الواجهة الوحيدة للوصول لقاعدة البيانات عبر **Prisma**. كل جدول له Repository (CRUD + استعلامات خاصة).
- **Logger**: نظام تسجيل (Winston) للأخطاء والعمليات في ملفات `.log`.
- **Backup Manager**: نسخ/استعادة ملف قاعدة البيانات.
- **Report Generators**: توليد PDF (PDFKit/Puppeteer) و Excel (ExcelJS).

> **مبدأ الاعتماد (Dependency Rule):** الطبقات الداخلية لا تعرف شيئًا عن الخارجية. الـ Controller يعتمد على Service، والـ Service يعتمد على واجهة Repository (Interface) لا على Prisma مباشرة — ما يسهّل الاختبار (Unit Testing) واستبدال قاعدة البيانات مستقبلًا.

## 4. الأمان والمصادقة (Security & Auth)

- **المصادقة المحلية**: تسجيل دخول باسم مستخدم وكلمة مرور.
- **تشفير كلمات المرور**: **bcrypt** (Salt + Hash) — لا تُخزّن كلمات المرور كنص صريح أبدًا.
- **الجلسات**: رمز جلسة (Session Token / JWT محلي) يُخزّن بأمان ويُرفق مع كل طلب.
- **نظام الصلاحيات RBAC**: ثلاثة مستويات — المستخدم (User) ← الدور (Role) ← الصلاحية (Permission). كل طلب يمر عبر Middleware يتحقق من امتلاك المستخدم للصلاحية المطلوبة (مثال: `invoices.create`, `equipment.delete`).
- **Audit Log**: تسجيل كل عملية حساسة (من، ماذا، متى، القيم قبل/بعد) في جدول `audit_logs`.
- **عزل الشبكة**: الخدمة الخلفية تستمع فقط على `127.0.0.1` ولا تقبل اتصالات خارجية.
- **تشفير قاعدة البيانات (اختياري)**: إمكانية استخدام SQLCipher لتشفير ملف `manar.db`.

## 5. الأدوار والصلاحيات

| الدور | الوصف | نطاق الصلاحيات |
|------|-------|----------------|
| مدير النظام (System Admin) | تحكم كامل + إعدادات النظام والمستخدمين | كل الصلاحيات |
| المدير العام (General Manager) | إشراف كامل على العمليات والتقارير | كل شيء عدا إعدادات النظام التقنية |
| المحاسب (Accountant) | الفواتير، المصروفات، القيود، التقارير المالية | المالية + قراءة باقي الوحدات |
| مدير المشاريع (Project Manager) | المشاريع، الإنجاز، ربط المصروفات والفواتير | المشاريع + قراءة العملاء والمعدات |
| مسؤول المعدات (Equipment Manager) | المعدات، الصيانة، الوقود، الأعطال | المعدات + الصيانة |
| مسؤول الموارد البشرية (HR Manager) | الموظفين، الحضور، الإجازات، الرواتب | الموارد البشرية |
| مستخدم عادي (Standard User) | عرض محدود حسب ما يُمنح له | قراءة فقط افتراضيًا |

الصلاحيات تُخزّن في قاعدة البيانات (وليست ثابتة في الكود) ليتمكن مدير النظام من تعديلها لكل دور.

## 6. تدفق البيانات (Data Flow) — مثال إصدار فاتورة

1. المستخدم يملأ نموذج الفاتورة في الواجهة (React) → التحقق المبدئي في الواجهة.
2. `apiClient` يرسل `POST /api/invoices` عبر HTTP إلى الخدمة المحلية.
3. **Auth Middleware** يتحقق من الجلسة → **RBAC Middleware** يتحقق من صلاحية `invoices.create`.
4. **Validation Middleware** يتحقق من المدخلات بـ Zod.
5. **InvoiceController** يستدعي **InvoiceService.create()**.
6. الـ Service يطبّق قواعد الأعمال (حساب الإجمالي، الضريبة، الخصم) ويستدعي عبر معاملة (Transaction):
   - `InvoiceRepository.create()` + `InvoiceItemRepository.createMany()` + `TransactionRepository` (قيد محاسبي).
7. تُسجّل العملية في **Audit Log**.
8. تُرجع الاستجابة → تحدّث الواجهة حالتها (Zustand) → إمكانية طباعة PDF فورًا.

## 7. النسخ الاحتياطي والاستعادة (Backup & Restore)

- **نسخ تلقائي**: مجدول (يومي/أسبوعي) يديره الـ Main Process عبر `node-cron`، ينسخ ملف `manar.db` إلى مجلد النسخ مع طابع زمني.
- **نسخ يدوي**: زر في الواجهة ينفّذ نسخة فورية.
- **الاستعادة**: اختيار ملف نسخة → إيقاف الاتصالات → استبدال قاعدة البيانات → إعادة التشغيل.
- **سجل النسخ**: جدول `backups` يحفظ تاريخ ومسار وحجم وحالة كل نسخة.
- **تصدير**: إمكانية تصدير قاعدة البيانات كاملة إلى مجلد يختاره المستخدم.

## 8. التقارير (Reporting)

- **PDF**: قوالب احترافية بترويسة الشركة (PDFKit أو Puppeteer لقوالب HTML معقدة) مع دعم العربية وRTL.
- **Excel**: تصدير الجداول والتقارير المالية عبر **ExcelJS**.
- **طباعة مباشرة**: عبر واجهة الطباعة في Electron.
- تقارير مصنّفة: يومية/أسبوعية/شهرية/سنوية لكل وحدة (عملاء، موظفين، معدات، مشاريع، فواتير، مصروفات، أرباح/خسائر).

## 9. المجموعة التقنية (Technology Stack)

**الواجهة الأمامية:** Electron · React 18 · TypeScript · Material UI (v5, RTL) · Zustand · React Router · Axios · Recharts (رسوم بيانية) · react-hook-form + Zod.

**الخلفية:** Node.js · Express · Prisma ORM · SQLite · bcrypt · jsonwebtoken · Zod · Winston (Logger) · node-cron (الجدولة) · ExcelJS · PDFKit.

**الأدوات والجودة:** Vite (بناء الواجهة) · electron-builder (الـ Installer) · ESLint · Prettier · Vitest/Jest (اختبارات) · Husky (Git hooks).

## 10. خصائص الجودة (Quality Attributes)

- **قابلية التوسع:** بنية معيارية (Modular) — كل وحدة مستقلة، يسهل إضافة وحدات جديدة.
- **الأداء:** SQLite سريع جدًا محليًا + فهارس (Indexes) على الأعمدة كثيرة الاستعلام + ترقيم الصفحات (Pagination).
- **العمل دون إنترنت:** كل شيء محلي 100%.
- **قابلية الصيانة:** Clean Architecture + SOLID + TypeScript صارم + اختبارات وحدة.
- **معالجة الأخطاء:** معالج أخطاء مركزي + استجابات موحّدة + تسجيل كامل.
- **التدقيق:** Audit Log شامل لكل العمليات الحساسة.
- **دعم العربية الكامل:** RTL في كل الواجهة + خطوط عربية + تنسيق تواريخ وأرقام عربية.
