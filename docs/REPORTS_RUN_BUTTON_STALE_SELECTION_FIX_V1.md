## نسب العيب

العيب **قائم مسبقًا (pre-existing)** منذ **Desktop 2026.5.9**، واكتُشف أثناء التحقّق من
**Desktop Production 2026.5.10**. **ليس انحدارًا من حزم المقبوضات** — حزم المقبوضات أضافت
بطاقة تقرير جديدة إلى مركز موجود أصلًا بهذا العيب، فظهر أثره على أحدث بطاقة فلُوحظ.

---

## السبب الجذري

زرّ «تشغيل» داخل بطاقة التقرير كان ينفّذ:

```tsx
onClick={(e) => { e.stopPropagation(); selectReport(rt.key); setTimeout(loadPreview, 0); }}
```

و`loadPreview` كانت `useCallback` تعتمد على `selected` من حالة المكوّن. الدالّة المُمرَّرة إلى
`setTimeout` هي **قيمة تلك الرسمة** — أي الإغلاق (closure) الذي التقط `selected` **قبل** الضغط.
`setSelected` غير متزامن، و`setTimeout` تحتجز المرجع القديم، فحين ينطلق المؤقّت يُطلب:

```
GET /reports/<التقرير المحدَّد سابقًا>/preview
```

لا تقرير البطاقة المضغوطة. النتيجة الظاهرة للمستخدم: يضغط بطاقة «ب» فيُعرض تقرير «أ».

وللسبب نفسه كانت **الفلاتر** مأخوذة من الإغلاق القديم أيضًا، فتتسرّب فلاتر التقرير السابق
(مثل `customerId`) إلى طلب تقرير لا تخصّه.

### إثبات العيب قبل الإصلاح

اختبار الانحدار الجديد شُغّل على الكود **قبل** الإصلاح فسقط ٢٣ من ٢٨ حالة، برسائل تُظهر
البصمة الحرفية للإغلاق القديم:

```
expected 'invoices' to be 'expenses'
expected 'invoices' to be 'receipts'
expected 'payroll'  to be 'receipts'            ← بعد تهيئة payroll
expected 'customer-statement' to be 'employees' ← بعد تهيئة customer-statement
expected [ 'invoices', 'contracts' ] to deeply equal [ 'contracts', 'equipment' ]  ← ضغط متتابع
```

١٨ من ١٩ بطاقة كانت تنفّذ **التقرير المحدَّد سابقًا**. البطاقة الوحيدة الناجحة هي `invoices`
— وهي التقرير الابتدائي المحدَّد، أي الحالة الوحيدة التي صادف فيها الإغلاق القديم الصواب.

## الإصلاح

**الملف:** `frontend/src/pages/Reports.tsx` (الملفّ الوحيد المعدَّل في الإنتاج)

استُخرجت دالّة تنفيذ **صريحة الوسائط** لا تقرأ الحالة إطلاقًا:

```tsx
const runReport = useCallback(async (reportKey: string, params: Record<string, string>) => {
  …
  const res = await api.get(`/reports/${reportKey}/preview`, { params });
  …
}, [canView]);
```

| المسار | قبل | بعد |
|---|---|---|
| زرّ «تشغيل» في البطاقة | `selectReport(rt.key)` + `setTimeout(loadPreview, 0)` | `selectReport(rt.key)` + `runReport(rt.key, directRunParams(rt.key))` |
| «تهيئة ← تشغيل التقرير» | `loadPreview()` تقرأ `selected` | `loadPreview()` → `runReport(selected, buildParams())` — سلوك مطابق |
| زرّ «عرض التقرير» في قسم النتيجة | `loadPreview()` | كما هو |

**لماذا لا يعتمد الحلّ على التوقيت:** `runReport` تتلقّى المفتاح والوسائط كمعاملين، ويُنفَّذ
`api.get` تزامنيًا داخل معالج الضغط نفسه. لا `setTimeout`، ولا تأخير، ولا إعادة محاولة، ولا
انتظار لانتشار `setState`. صحّة النتيجة لا علاقة لها بترتيب الرسم.

**الفلاتر (`directRunParams`):** التشغيل المباشر لبطاقة **مختلفة** يستعمل قيم البدء التي
يضبطها أثر تغيّر `selected` (`from`/`to` من الفترة العالمية، وبقيّة الفلاتر فارغة) — فلا تتسرّب
فلاتر التقرير السابق. أمّا الضغط على بطاقة التقرير **المحدَّد أصلًا** فيحترم الفلاتر التي
ضبطها المستخدم له.

**تغيير مساند:** `REPORT_TYPES` صار تصديرًا مُسمّى (`export const`) ليقود اختبار الانحدار من
السجلّ الفعلي بدل قائمة مكتوبة يدويًا. لا أثر على وقت التشغيل ولا على العرض.

## تغطية الانحدار

**الملف:** `frontend/src/pages/__tests__/reportsRunButtonSelection.test.tsx` — ٢٨ حالة، كلّها ناجحة.

التغطية **مسوقة بالسجلّ**: `it.each(REPORT_TYPES…)` تمرّ على **كلّ** بطاقة في `REPORT_TYPES`
(١٩ حاليًا) وتؤكّد أن **مفتاح البطاقة المضغوطة == المفتاح المنفَّذ**، بقراءة عنوان الطلب
الفعلي `/reports/<key>/preview` من طبقة الـ API المُزيَّفة. إضافة تقرير جديد مستقبلًا تدخل
التغطية تلقائيًا بلا تعديل الاختبار.

| السيناريو | النتيجة |
|---|---|
| كلّ بطاقة من التسعة عشر — الضغط المباشر | ✅ المفتاح المنفَّذ == مفتاح البطاقة |
| المحدَّد «أ» ← الضغط على «ب» (payroll ← receipts) | ✅ يُنفَّذ `receipts` |
| المحدَّد == بطاقة الضغط (expenses) | ✅ يعمل طبيعيًا |
| بلا تهيئة سابقة — «المقبوضات» مباشرة | ✅ يُنفَّذ `receipts` |
| ضغط متتابع سريع (contracts ← equipment) | ✅ `['contracts','equipment']` بالترتيب |
| عدم تسرّب فلاتر التقرير السابق | ✅ `customerId` غائب عن طلب `employees` |
| «تهيئة ← تشغيل التقرير» (المسار التقليدي) | ✅ يعمل كما كان |
| «عرض التقرير» من قسم النتيجة | ✅ يعمل كما كان |
| النتيجة المعروضة في الواجهة بعد التشغيل المباشر | ✅ نتيجة التقرير المضغوط |
