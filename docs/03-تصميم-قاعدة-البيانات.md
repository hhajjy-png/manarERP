# تصميم قاعدة البيانات — Database Design

**نظام شركة المنار** — قاعدة بيانات SQLite تُدار عبر Prisma ORM.

المخطط الكامل موجود في الملف: `backend/prisma/schema.prisma`. هذه الوثيقة تشرح الجداول والعلاقات ومبررات التصميم.

---

## 1. مخطط العلاقات (ERD مبسّط)

```
                         ┌──────────┐        ┌──────────────┐
                         │  roles   │◄───────│ role_perms   │───────►┌──────────────┐
                         └────┬─────┘        └──────────────┘        │ permissions  │
                              │                                       └──────────────┘
                              │ 1..N
                         ┌────▼─────┐         ┌──────────────┐
                         │  users   │────────►│  audit_logs  │
                         └────┬─────┘ 1..N    └──────────────┘
                              │ 0..1          ┌──────────────┐
                              └──────────────►│   backups    │
                                              └──────────────┘
   ┌────────────┐ 1..1   ┌────────────┐
   │  employees │◄───────│   users    │
   └─────┬──────┘        └────────────┘
         │ 1..N → attendance, leaves, deductions, bonuses, payroll, performance_reviews
         │ 1..N → projects (كمدير مشروع)
         │ 1..N → expenses (كمعتمِد)

   ┌────────────┐ 1..N   ┌────────────┐ 1..N   ┌──────────────┐
   │ customers  │───────►│  projects  │───────►│   invoices   │
   └─────┬──────┘        └─────┬──────┘        └──────┬───────┘
         │ 1..N                │ 1..N                 │ 1..N
         │ invoices            │ expenses             ├──► invoice_items
                               │ project_documents    └──► payments

   ┌────────────┐ 1..N   ┌──────────────────┐
   │ equipment  │───────►│ maintenance_records, fuel_logs,         │
   └────────────┘        │ breakdowns, spare_part_usage           │
                         └──────────────────┘

   ┌────────────┐ 1..N   ┌────────────┐         ┌──────────────┐
   │ suppliers  │───────►│  invoices  │  +      │   expenses   │
   └────────────┘        └────────────┘         └──────────────┘

   ┌──────────────┐   ┌──────────┐
   │ transactions │   │ settings │   (مستقلة / مرجعية)
   └──────────────┘   └──────────┘
```

## 2. الجداول الأساسية المطلوبة

تغطّي قاعدة البيانات كل الجداول المطلوبة، بالإضافة إلى جداول مساعدة لاستكمال الوظائف:

| الجدول | الغرض |
|--------|-------|
| `users` | حسابات المستخدمين + ربطها بالأدوار والموظفين |
| `roles` | الأدوار (مدير نظام، محاسب، مدير مشاريع...) |
| `permissions` | الصلاحيات الذرّية (invoices.create ...) |
| `role_permissions` | جدول وصل (Many-to-Many) بين الأدوار والصلاحيات |
| `employees` | بيانات الموظفين |
| `attendance` | الحضور والانصراف |
| `leaves` | الإجازات |
| `deductions` / `bonuses` | الخصومات والمكافآت |
| `payroll` | كشوف الرواتب الشهرية |
| `performance_reviews` | تقييم الأداء |
| `customers` | العملاء |
| `projects` | المشاريع |
| `project_documents` | مستندات وصور المشاريع |
| `equipment` | المعدات والآليات |
| `maintenance_records` | سجلات الصيانة + تنبيهات الصيانة الدورية |
| `fuel_logs` | استهلاك الوقود |
| `breakdowns` | سجل الأعطال |
| `spare_part_usage` | قطع الغيار المستخدمة |
| `suppliers` | الموردون |
| `invoices` | الفواتير (عملاء + موردين عبر حقل `direction`) |
| `invoice_items` | بنود الفواتير |
| `payments` | دفعات/تحصيلات الفواتير |
| `expenses` | المصروفات |
| `transactions` | القيود المحاسبية (دفتر اليومية/الأستاذ) |
| `audit_logs` | سجل التدقيق |
| `backups` | سجل النسخ الاحتياطي |
| `settings` | إعدادات النظام (مفتاح/قيمة) |

> الجداول الإضافية (الإجازات، الخصومات، المكافآت، تقييم الأداء، الوقود، الأعطال، قطع الغيار، الدفعات، مستندات المشاريع) أُضيفت لتغطية المزايا المذكورة في المتطلبات بشكل كامل دون حشرها في حقول نصية.

## 3. قرارات التصميم الرئيسية

**الفواتير الموحّدة:** بدل جدولين منفصلين لفواتير العملاء والموردين، استُخدم جدول `invoices` واحد مع حقل `direction` (SALES / PURCHASE). هذا يقلّل التكرار ويوحّد منطق التحصيل والسداد، مع ربط اختياري بـ `customerId` أو `supplierId`.

**RBAC على ثلاثة مستويات:** المستخدم ← الدور ← الصلاحية. الصلاحيات مخزّنة في قاعدة البيانات (وليست ثابتة في الكود)، ما يسمح لمدير النظام بتعديل صلاحيات أي دور دون تغيير الكود. جدول `role_permissions` يربط الأدوار بالصلاحيات (Many-to-Many).

**القيود المحاسبية (`transactions`):** تتبع نموذج القيد المزدوج المبسّط (debit / credit) مع `referenceType` و`referenceId` لربط كل قيد بمصدره (فاتورة، مصروف، راتب). هذا يتيح بناء دفتر اليومية والأستاذ العام وكشوف الحسابات.

**ربط الموظف بالمستخدم:** علاقة 1..1 اختيارية بين `employees` و`users` — ليس كل موظف له حساب دخول، وليس كل مستخدم موظفًا (مثل مدير النظام التقني).

**الحذف المتسلسل (Cascade):** البنود التابعة (بنود الفاتورة، الدفعات، سجلات الصيانة، الحضور...) تُحذف تلقائيًا عند حذف السجل الأب عبر `onDelete: Cascade`، بينما العلاقات المرجعية المهمة (العميل في المشروع) تُمنع من الحذف للحفاظ على سلامة البيانات.

**الأرشفة بدل الحذف:** العملاء والموردون لديهم حقل `isArchived` للأرشفة بدل الحذف النهائي، حفاظًا على التاريخ المالي المرتبط بهم.

## 4. الفهارس (Indexes)

أُضيفت فهارس على الأعمدة كثيرة الاستعلام والفلترة لتسريع الأداء:

- مفاتيح خارجية (`customerId`, `projectId`, `equipmentId`, `employeeId`...) — لتسريع الـ JOINs.
- أعمدة الحالة (`status`, `type`, `direction`, `category`) — لتسريع الفلترة.
- أعمدة التواريخ (`date`, `issueDate`, `createdAt`, `nextDueDate`) — لتسريع التقارير الزمنية والتنبيهات.
- قيود تفرّد مركّبة: `(employeeId, date)` في الحضور، `(employeeId, month, year)` في الرواتب، `(roleId, permissionId)` في الصلاحيات — لمنع التكرار.

## 5. القيم المسموحة للحقول النصية (Enums منطقية)

> SQLite لا يدعم `enum` في Prisma، لذا القيم تُخزّن كنص ويُفرض التحقق منها في طبقة Zod بالخلفية.

| الحقل | القيم |
|------|-------|
| `Customer.type` | GOVERNMENT, PRIVATE |
| `User/Employee.status` | ACTIVE, ON_LEAVE, TERMINATED |
| `Equipment.status` | OPERATIONAL, UNDER_MAINTENANCE, IDLE, BROKEN |
| `Project.status` | PLANNED, ACTIVE, ON_HOLD, COMPLETED, CANCELLED |
| `Invoice.direction` | SALES, PURCHASE |
| `Invoice.status` | UNPAID, PARTIAL, PAID, OVERDUE, CANCELLED |
| `Expense.category` | FUEL, SALARIES, MAINTENANCE, RENT, PURCHASES, EQUIPMENT, SERVICES, OTHER |
| `Expense.status` | PENDING, APPROVED, REJECTED |
| `Transaction.type` | REVENUE, EXPENSE, TRANSFER, ADJUSTMENT |
| `Payroll.status` | DRAFT, APPROVED, PAID |
| `Maintenance.type` | PREVENTIVE, CORRECTIVE |
| `Backup.type` | MANUAL, AUTO, SCHEDULED |

## 6. البيانات الأولية (Seed)

عند أول تشغيل، يملأ `prisma/seed.ts` قاعدة البيانات بـ:

1. **الصلاحيات** لكل وحدة (create/read/update/delete/approve).
2. **الأدوار السبعة** المطلوبة مع ربطها بالصلاحيات المناسبة.
3. **مستخدم مدير نظام افتراضي** (`admin`) بكلمة مرور مبدئية يُطلب تغييرها عند أول دخول.
4. **إعدادات الشركة الأساسية** (الاسم، نسبة الضريبة الافتراضية، إعدادات النسخ الاحتياطي).
